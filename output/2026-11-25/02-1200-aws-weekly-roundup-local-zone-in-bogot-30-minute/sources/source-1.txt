AWS Weekly Roundup: Local Zone in Bogotá, 30-minute Lambda timeout, and more (November 24, 2026)
|  | 
Some limits shape architecture more than any feature does. AWS Lambda launched in 2014 with a 60-second timeout, moved to 5 minutes in 2015 and to 15 minutes in 2018, and then stayed there for eight years. Last week the limit doubled, and in the same week Lambda learned to run on GPUs and gave platform teams their own runtimes. That is a lot of Lambda for one week.
Two other threads ran through the week. A new AWS Local Zone in Bogotá brought AWS infrastructure closer to users in Colombia. And AWS Security Token Service (AWS STS), Amazon Cognito, and Amazon CloudFront each shipped a piece of identity for agents: who an agent is when it shows up at your door, and how little it should be allowed to do. Now, let’s get into this week’s AWS news…
Headlines
AWS Local Zone in Bogotá, Colombia – AWS opened a new Local Zone in Bogotá, so you can now run applications that need single-digit millisecond latency closer to users in Colombia. AWS Local Zones place compute, storage, and networking near large metropolitan areas with the same APIs and tools as a Region, for workloads like real-time gaming, live streaming, and financial transactions. The Bogotá Local Zone supports Amazon EC2 C7i, M7i, and R7i instances, Amazon EBS gp3, gp2, and io1 volumes with local snapshots, Amazon S3 One Zone-Infrequent Access, Amazon ECS, Amazon EKS, AWS Direct Connect, and Application Load Balancer. To start, enable us-east-1-bog-1a in AWS Global View.
AWS Lambda now supports a 30-minute timeout for on-demand Event Functions – You can now configure any Event Function with a timeout of up to 30 minutes (1,800 seconds), double the previous limit, for synchronous, asynchronous, and event source mapping invocations. On Lambda Managed Instances, synchronous invocations also go to 30 minutes, while asynchronous and event source mapping invocations keep the 90-minute timeout from September. Standard Lambda pricing applies, in all commercial Regions. Agentic requests that chain model and tool calls, media transcoding, and file conversion are the workloads AWS calls out. Before raising the value, read the considerations in the Compute blog post: a service that invokes your function synchronously applies its own timeout, client read and socket timeouts need to be longer, and a NAT gateway drops idle connections after 350 seconds, so long calls need keep-alives. For longer work, durable functions still run for up to a year, and now emit OpenTelemetry traces.
AWS Lambda now supports GPU instances for Event Functions on Lambda Managed Instances – You can now run GPU-accelerated inference, media processing, rendering, and scientific computing as Lambda functions, packaged as OCI container images, with no GPU drivers, CUDA versions, or AMIs to reconcile. In the walkthrough, four concurrent requests shared one copy of the model on a single GPU and finished in about the same time as one. It’s optimized for inference with custom models, on G-series instances from G4dn to G6e. You pay the EC2 instance fee (Savings Plans and Reserved Instances apply), a 9.75% management fee for GPU instances, and $0.20 per million requests.
Last week’s launches
Here are some launches and updates from this past week that caught my attention:
Amazon Polly now supports voice cloning – You can now create a custom voice in Amazon Polly from a few minutes of recordings of a consenting speaker, running on the Polly generative engine. It launches in seven languages, including English, Spanish, and Portuguese, and each cloned voice speaks the language it was recorded in. Polly doesn’t keep the recordings or train on them. Creating a voice is free, and you pay for the speech you synthesize. It’s a gated release, so request access through your account team. The ML blog post covers brand-voice use cases for contact centers, voice agents, and content.
AWS Lambda now supports customer-managed runtimes – You can now manage a Lambda runtime as its own resource, separate from function deployment. Platform teams package approved SDKs, certificates, and security or monitoring agents as an OCI image in Amazon ECR, and functions pick up updates as Lambda recycles execution environments, with no per-function redeploys. Updates can be staged, with health metrics and rollback. There’s no additional charge, and the Compute blog walkthrough shows the platform-team workflow.
AWS STS announces GetScopedCredentials to scope down permissions at runtime – You can now take the temporary credentials a workload already holds and derive narrower ones, cutting permissions, session duration, or both. The result keeps the caller’s original identity, and permissions only ever narrow, so a sub-agent can never end up with more access than whoever created it. Access to the API is controlled with IAM policies, and every call lands in AWS CloudTrail. It’s available in all commercial Regions and beyond, including GovCloud (US) and China.
Amazon Cognito now supports dynamic client registration – You can now let MCP clients and AI agents register themselves at runtime (RFC 7591) instead of creating an app client in advance for each one. You choose between requiring an access token with a registration scope or opening registration to any client, and dynamically registered clients carry a client ID prefix so you can filter and manage them with the rest. It’s available on the Essentials and Plus plans, and client ID metadata documents arrived the same week.
Amazon CloudFront Functions now supports network calls – You can now call your own APIs from a function with cf.fetch() and act on the response, so authorization, personalization, or fraud checks that used to need Lambda@Edge or a trip to the origin can run at the edge. AWS’s own example: check an AI agent’s permissions and usage budget before the request reaches your API or MCP server. Network calls cost $0.10 per million on top of invocation charges and are included in the Pro flat-rate plan and above. The Networking blog post also covers cf.beacon() for background analytics.
Amazon Aurora DSQL now supports multi-Region peering across continents – You can now build a multi-Region Amazon Aurora DSQL cluster with peers on different continents, such as US East (N. Virginia) and Europe (Ireland), and read and write to one strongly consistent database from both. It was a busy week for DSQL: PL/pgSQL functions and procedures arrived, and storage upgrades brought up to 50% higher write throughput at no additional cost.

Other AWS news
Here are some additional posts and resources that you might find interesting:
How the BMW Group governs hundreds of agents across thousands of developers – With more than 12,500 developers in R&D, BMW treats governance as deterministic code outside the agent’s reasoning loop, mostly in the CI/CD pipeline, so neither the agent nor its prompts can override it.
AI coding agents on Amazon EC2 Mac: How Cognition scales Devin for macOS – Cognition starts a fresh macOS VM for each Devin session in under a minute on Amazon EC2 Mac hosts across six Regions. The detail worth stealing: sessions are decoupled from hosts, and Cognition reports that about 90% release their VM when idle and resume from a snapshot in seconds.
How Klaviyo processes 3 billion daily events at scale with Amazon MSK Express – Timely reading for Black Friday week. Klaviyo moved from RabbitMQ to Amazon MSK Express brokers to absorb roughly 7 times normal event volume during Black Friday and Cyber Monday. Running one set of processors across three priority topics, instead of separate infrastructure per level, cut costs by roughly 30%, according to the team.
